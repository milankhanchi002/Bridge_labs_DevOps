Imperative vs Declarative
Imperative ----You tell the system what actions to perform.
            az group create ...
            az network vnet create ...
            az network vnet subnet create ...
            az network nsg create ...
            az network vnet subnet update ...

Declarative
You describe the desired final state.         

I want:
VNet: app-vnet
Address space: 10.0.0.0/16
Subnets:
  web: 10.0.1.0/24
  app: 10.0.2.0/24
  db: 10.0.3.0/24   
  This is what I want my infrastructure to look like.

-----------------------------------------------------------------------------------------------------------------

IAC -Infrastructure as Code. ---Infrastructure as Code = managing infrastructure through machine-
readable code/configuration instead of relying on manual configuration.

Infrastructure Code
       ↓
      Git
       ↓
     Review
       ↓
     Pipeline
       ↓
     Azure
     
This gives you:
Repeatability
You can recreate the environment.
Version control
You can see:
Who changed infrastructure?
What changed?
When?

Automation
CI/CD can deploy infrastructure.

Consistency
Dev/staging/prod can be created from controlled definitions.

The IaC system tries to make actual infrastructure conform to the desired definition.
This concept becomes even more important when we reach Terraform.          


configuration drift.------But someone goes into Portal and manually adds something now dont match with git repo.

Idempotency Then you deploy the same definition again.
A good declarative system should not blindly create Instead, it determines that the desired resource 
already exists and makes the necessary changes, if any.
That's the basic idea behind idempotent infrastructure operations.
