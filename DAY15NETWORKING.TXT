                 MODULE: NETWORK CONFIGURATION (ifconfig)
================================================================================

1. INTRODUCTION
--------------------------------------------------------------------------------
Command      : ifconfig (Interface Configuration)
Binary Path  : /sbin/ifconfig or /usr/sbin/ifconfig
Package      : net-tools
Description  : A core Linux network management tool used to query, configure, 
               enable/disable, and troubleshoot Network Interface Cards (NICs) 
               such as Ethernet (eth0, ens33), Wi-Fi (wlan0), and Loopback (lo).
Modern Alt   : `ip` command (ip addr, ip link, ip route).


2. REAL-WORLD USES
--------------------------------------------------------------------------------
1. Network Status Check  : View assigned IPv4/IPv6 addresses, subnet mask, & MAC.
2. Temporary IP Config   : Quick IP reassignment for testing/temporary environments.
3. Hardware Diagnostics  : Track packet corruption, CRC errors, and drops via RX/TX.
4. Security Testing      : Perform MAC Address spoofing for security audits.
5. Storage Optimization  : Set Jumbo Frames (MTU 9000) for high-speed NFS/SAN networks.


3. KEY FLAGS & COMMAND VARIATIONS
--------------------------------------------------------------------------------
Task                                    Command
--------------------------------------------------------------------------------
View active interfaces                : ifconfig
View ALL interfaces (including DOWN)  : ifconfig -a
Short summary of all interfaces       : ifconfig -s
View specific interface status        : ifconfig ens33
Disable an active interface           : sudo ifconfig ens33 down
Enable a disabled interface           : sudo ifconfig ens33 up
Assign static IP                      : sudo ifconfig ens33 192.168.1.100
Assign IP with Subnet Mask            : sudo ifconfig ens33 192.168.1.100 netmask 255.255.255.0
Spoof / Change MAC Address            : sudo ifconfig ens33 hw ether 00:11:22:33:44:55
Set Jumbo Frame MTU Size              : sudo ifconfig ens33 mtu 9000


4. SAMPLE OUTPUT BREAKDOWN
--------------------------------------------------------------------------------
Command: ifconfig ens33

Sample Output:
ens33: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.1.105  netmask 255.255.255.0  broadcast 192.168.1.255
        inet6 fe80::a00:27ff:fe4e:66a1  prefixlen 64  scopeid 0x20<link>
        ether 08:00:27:4e:66:a1  txqueuelen 1000  (Ethernet)
        RX packets 10425  bytes 12543011 (12.5 MB)
        RX errors 0  dropped 0  overruns 0  frame 0
        TX packets 8512  bytes 1024512 (1.0 MB)
        TX errors 0  dropped 0  overruns 0  carrier 0  collisions 0

Metrics Explained:
- UP, RUNNING         : Interface hardware is active and connected to network.
- mtu 1500            : Maximum packet size (1500 bytes for standard Ethernet).
- inet 192.168.1.105  : Assigned active IPv4 address.
- netmask 255.255.255.0: Subnet mask (/24 network).
- ether 08:00:27:...  : Physical Layer-2 MAC address.
- RX / TX packets     : Total data volume received (RX) and transmitted (TX).
- RX errors / dropped : Hardware/cable error counter (non-zero indicates hardware/cable issues).


5. REAL-WORLD TROUBLESHOOTING SCENARIO
--------------------------------------------------------------------------------
Scenario: Server has no Internet/Network connectivity.

Troubleshooting Steps:
1. Check active interfaces          : Execute `ifconfig`.
2. Check hidden/disabled interfaces : Execute `ifconfig -a`.
3. Bring up disabled interface      : Execute `sudo ifconfig ens33 up`.
4. Assign test IP if DHCP failed    : Execute `sudo ifconfig ens33 192.168.1.150 netmask 255.255.255.0`.
5. Check for cable/switch fault     : Look at `RX errors` / `dropped`. High numbers 
                                      indicate bad LAN cable or switch port.


6. REVISION CHEATSHEET
--------------------------------------------------------------------------------
- `ifconfig` changes are IN-MEMORY and TEMPORARY (revert upon reboot).
- For permanent IP assignment, write configuration to Netplan or NetworkManager.
- Always run `ifconfig -a` if an expected interface is missing from `ifconfig`.

================================================================================
                      LINUX SYSTEM ADMINISTRATION NOTES
                 MODULE: MODERN NETWORK MANAGEMENT (ip)
================================================================================

1. INTRODUCTION
--------------------------------------------------------------------------------
Command      : ip (IP Route / Address / Link Management)
Binary Path  : /sbin/ip or /usr/sbin/ip
Package      : iproute2
Description  : The modern, powerful, and official replacement for legacy tools 
               like `ifconfig`, `route`, and `arp`. Used by Linux kernel sysadmins 
               to manage network interfaces, IP addresses, routing tables, and ARP.
Modern Alt   : Replaces legacy `ifconfig`, `route -n`, `arp -a`.


2. REAL-WORLD USES
--------------------------------------------------------------------------------
1. Interface Management  : Enable/disable interfaces, change MTU, modify MAC.
2. IP Addressing         : Assign multiple IPv4/IPv6 addresses to a single interface.
3. Routing Table Control : View, add, modify, and delete default gateway & routes.
4. ARP / Neighbor Cache  : Inspect and flush local Layer-2 ARP table entries.
5. Network Troubleshooting: Trace packet routing decisions (`ip route get`).


3. KEY FLAGS & COMMAND VARIATIONS
--------------------------------------------------------------------------------
OBJECTS IN `ip` COMMAND:
- `ip addr` (or `ip a`)   : Manage IP addresses on interfaces.
- `ip link` (or `ip l`)   : Manage link state (UP/DOWN, MTU, MAC).
- `ip route` (or `ip r`)  : Manage routing tables and default gateways.
- `ip neigh` (or `ip n`)  : Manage ARP table / Neighbor cache.

Task                                    Command
--------------------------------------------------------------------------------
List all IP addresses & interfaces    : ip addr show  (or `ip a`)
List specific interface IP            : ip addr show dev ens33
Add IP address to interface           : sudo ip addr add 192.168.1.100/24 dev ens33
Delete IP address from interface      : sudo ip addr del 192.168.1.100/24 dev ens33
List link status (MAC, MTU, state)    : ip link show
Bring interface UP                    : sudo ip link set dev ens33 up
Bring interface DOWN                  : sudo ip link set dev ens33 down
Change MTU size                       : sudo ip link set dev ens33 mtu 9000
View routing table                    : ip route show (or `ip r`)
Add default gateway                   : sudo ip route add default via 192.168.1.1
Delete default gateway                : sudo ip route del default
View ARP cache (IP to MAC mappings)   : ip neigh show


4. SAMPLE OUTPUT BREAKDOWN
--------------------------------------------------------------------------------
Command: ip a show dev ens33

Sample Output:
2: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    link/ether 08:00:27:4e:66:a1 brd ff:ff:ff:ff:ff:ff
    inet 192.168.1.105/24 brd 192.168.1.255 scope global dynamic ens33
       valid_lft 86120sec preferred_lft 86120sec
    inet6 fe80::a00:27ff:fe4e:66a1/64 scope link 
       valid_lft forever preferred_lft forever

Metrics Explained:
- <UP,LOWER_UP>       : Interface is enabled in OS (UP) and physical cable is plugged in (LOWER_UP).
- state UP            : Operational status of the network card is active.
- link/ether ...      : Layer-2 Hardware MAC address.
- inet 192.168.1.105/24: Active IPv4 address with CIDR notation (/24 = 255.255.255.0).
- scope global        : IP is globally routable on the network.
- dynamic             : IP was assigned automatically via DHCP.


5. REAL-WORLD TROUBLESHOOTING SCENARIO
--------------------------------------------------------------------------------
Scenario: Server cannot reach the Internet, but can ping local network IPs.

Troubleshooting Steps:
1. Check interface status           : Execute `ip link show`. Look for `state UP`.
2. Verify assigned IP & Subnet      : Execute `ip addr show`. Ensure valid IP exists.
3. Check Routing Table / Gateway    : Execute `ip route show`. Look for:
                                      `default via 192.168.1.1 dev ens33`
4. Fix missing Gateway (if needed)  : Execute `sudo ip route add default via 192.168.1.1 dev ens33`.
5. Test routing decision            : Execute `ip route get 8.8.8.8` to see which 
                                      gateway/interface handles the packet.


6. REVISION CHEATSHEET
--------------------------------------------------------------------------------
- Syntax Pattern: `ip <OBJECT> <ACTION> <DEVICE>` (e.g., `ip addr add ... dev ens33`).
- Supports CIDR notation directly (e.g., `/24`, `/16`), unlike `ifconfig`.
- Supports multiple IP addresses on a single interface without virtual aliases.
- All `ip` command changes are IN-MEMORY and TEMPORARY (revert upon reboot).

================================================================================
                      LINUX SYSTEM ADMINISTRATION NOTES
                 MODULE: ETHTOOL FLAGS & COMMANDS REFERENCE
================================================================================

1. INTRODUCTION
--------------------------------------------------------------------------------
Command      : ethtool (Ethernet Card Display & Control Tool)
Binary Path  : /sbin/ethtool or /usr/sbin/ethtool
Package      : ethtool
Description  : Low-level utility to inspect, query, and configure Network Interface 
               Card (NIC) hardware drivers, link speeds, ring buffers, and offloading.


2. COMPREHENSIVE FLAGS & COMMANDS CHEAT SHEET
--------------------------------------------------------------------------------
Flag    Purpose / Action                        Example Command
--------------------------------------------------------------------------------
(None)  Display basic link speed & status      : ethtool ens33
-i      Display driver & firmware information  : ethtool -i ens33
-S      Display low-level hardware statistics  : ethtool -S ens33
-s      Set/Modify NIC speed, duplex, autoneg  : sudo ethtool -s ens33 speed 1000 duplex full autoneg on
-p      Physically blink NIC LED light (ID)    : sudo ethtool -p ens33 15
-g      Query Ring Buffer sizes (Rx/Tx queues) : ethtool -g ens33
-G      Set/Increase Ring Buffer sizes         : sudo ethtool -G ens33 rx 4096 tx 4096
-k      Query Hardware Offloading features     : ethtool -k ens33
-K      Enable/Disable Hardware Offloading     : sudo ethtool -K ens33 tso off gso off
-d      Register dump (Raw driver data)       : ethtool -d ens33
-e      EEPROM dump of NIC                     : ethtool -e ens33


3. DETAILED USAGE BREAKDOWN & EXAMPLES
--------------------------------------------------------------------------------
1. Checking Hardware Driver & Firmware (-i):
   $ ethtool -i ens33
   Use: Check if the kernel is using the correct NIC driver (e.g., e1000e, i40e).

2. Checking Low-level Hardware Errors (-S):
   $ ethtool -S ens33 | grep -i error
   Use: Inspect rx_crc_errors, rx_missed_errors, or tx_aborted_errors to diagnose 
        damaged Ethernet cables or failing switch ports.

3. Forcing Speed and Duplex Settings (-s):
   $ sudo ethtool -s ens33 speed 100 duplex full autoneg off
   Use: Force a misbehaving 1Gbps card stuck at 10Mbps back to a stable speed.

4. Blinking Physical Port LED (-p):
   $ sudo ethtool -p ens33 30
   Use: Blinks the physical port LED on the back of a server for 30 seconds so you 
        can identify which physical cable to unplug.

5. Ring Buffer Capacity Optimization (-g / -G):
   $ ethtool -g ens33                 # Check current vs max allowed ring buffer
   $ sudo ethtool -G ens33 rx 4096    # Max out RX buffer to prevent dropped packets


4. REAL-WORLD TROUBLESHOOTING SCENARIO
--------------------------------------------------------------------------------
Scenario: Server is dropping network packets under heavy traffic load.

Troubleshooting Steps:
1. Check Hardware Errors   : `ethtool -S ens33 | grep -i drop`
                            (If rx_discards/rx_nodesc is high, buffers are full).
2. Check Current Buffers   : `ethtool -g ens33`
                            (Notice Current RX buffer is set to 256, but Max is 4096).
3. Expand Ring Buffer Size : `sudo ethtool -G ens33 rx 4096 tx 4096`
4. Re-verify Packet Drops  : Run `ethtool -S ens33` again to ensure drop count stops increasing.


5. REVISION CHEATSHEET
--------------------------------------------------------------------------------
- Lowercase flags (`-i`, `-g`, `-k`) are generally used for QUERYING information.
- Uppercase flags (`-G`, `-K`) or `-s` are used for MODIFYING/SETTING parameters.
- Modifying settings requires `sudo` or `root` privileges.
- All `ethtool` flags apply changes IN-MEMORY (reverts upon server reboot).

1. INTRODUCTION
--------------------------------------------------------------------------------
Command      : nmcli (NetworkManager Command Line Interface)
Binary Path  : /usr/bin/nmcli
Package      : NetworkManager
Description  : A command-line tool used for controlling NetworkManager and 
               managing network configurations permanently without manually 
               editing configuration files.
Replaces     : Manual editing of `/etc/sysconfig/network-scripts/` or Netplan files.


2. REAL-WORLD USES
--------------------------------------------------------------------------------
1. Persistent Network Config : Set static IP, Gateway, and DNS that survive reboots.
2. Wi-Fi Management          : Scan, connect, and disconnect Wi-Fi networks in CLI.
3. Connection Management     : Create, modify, enable (up), and disable (down) profiles.
4. Interface Monitoring      : Check physical device status and connection profiles.
5. Quick Network Toggling    : Turn off/on entire networking stack (`nmcli networking`).


3. KEY FLAGS & COMMAND VARIATIONS
--------------------------------------------------------------------------------
OBJECTS IN `nmcli` COMMAND:
- `nmcli device` (or `nmcli d`)     : Manage physical/virtual network cards.
- `nmcli connection` (or `nmcli c`) : Manage network configuration profiles.
- `nmcli radio` (or `nmcli r`)      : Manage Wi-Fi / WWAN radio switches.

Task                                    Command
--------------------------------------------------------------------------------
Check device/interface status         : nmcli device status
Check detailed device info            : nmcli device show ens33
List all connection profiles          : nmcli connection show
Activate a connection profile         : sudo nmcli connection up "static-ens33"
Deactivate a connection profile       : sudo nmcli connection down "static-ens33"
Add new Static IP connection profile  : sudo nmcli connection add type ethernet con-name "static-ens33" ifname ens33 ip4 192.168.1.100/24 gw4 192.168.1.1
Modify DNS on existing connection     : sudo nmcli connection modify "static-ens33" ipv4.dns "8.8.8.8 1.1.1.1"
Switch connection from DHCP to Static : sudo nmcli connection modify "static-ens33" ipv4.method manual
Reload modified connection profile   : sudo nmcli connection reload && sudo nmcli connection up "static-ens33"
Scan available Wi-Fi networks         : nmcli device wifi list
Connect to a Wi-Fi network            : sudo nmcli device wifi connect "SSID_NAME" password "WIFI_PASSWORD"


4. SAMPLE OUTPUT BREAKDOWN
--------------------------------------------------------------------------------
Command: nmcli device status

Sample Output:
DEVICE  TYPE      STATE      CONNECTION 
ens33   ethernet  connected  Wired connection 1 
lo      loopback  unmanaged  --         
wlan0   wifi      disconnected --

Metrics Explained:
- DEVICE (ens33)      : Physical or virtual network card name.
- TYPE (ethernet)     : Interface type (ethernet, wifi, loopback, bridge, bond).
- STATE (connected)   : Network state (connected, disconnected, unmanaged).
- CONNECTION          : Active connection profile name attached to the device.


5. REAL-WORLD TROUBLESHOOTING SCENARIO
--------------------------------------------------------------------------------
Scenario: Configure a permanent Static IP (192.168.1.150/24), Gateway (192.168.1.1), 
          and DNS (8.8.8.8) on interface `ens33`.

Troubleshooting / Implementation Steps:
1. Identify Device Name      : Run `nmcli device status` (e.g., `ens33`).
2. Modify Existing Profile   : Run the following commands:
   $ sudo nmcli connection modify "Wired connection 1" ipv4.addresses 192.168.1.150/24
   $ sudo nmcli connection modify "Wired connection 1" ipv4.gateway 192.168.1.1
   $ sudo nmcli connection modify "Wired connection 1" ipv4.dns "8.8.8.8"
   $ sudo nmcli connection modify "Wired connection 1" ipv4.method manual
3. Apply & Activate Changes  : Run `sudo nmcli connection up "Wired connection 1"`
4. Verify Configuration      : Run `ip addr show dev ens33` and `ip route`.


6. REVISION CHEATSHEET
--------------------------------------------------------------------------------
- Commands can be abbreviated: `nmcli d s` = `nmcli device status`, `nmcli c s` = `nmcli connection show`.
- Changes made via `nmcli` are PERSISTENT across system reboots.
- Always run `nmcli connection up <profile_name>` after modifying a connection.
- `ipv4.method manual` is required for Static IP; `ipv4.method auto` is for DHCP.

================================================================================
                      LINUX SYSTEM ADMINISTRATION NOTES
                 MODULE: NETWORK REACHABILITY DIAGNOSTICS (ping)
================================================================================

1. INTRODUCTION
--------------------------------------------------------------------------------
Command      : ping (Packet InterNet Groper)
Binary Path  : /bin/ping or /usr/bin/ping
Protocol     : ICMP (Internet Control Message Protocol - Layer 3 / Network Layer)
Description  : A fundamental diagnostic utility used to test network reachability 
               of a host, measure round-trip packet travel time (RTT), and detect 
               packet loss.


2. REAL-WORLD USES
--------------------------------------------------------------------------------
1. Host Reachability Check : Verify if a server, router, or website is online.
2. Latency Measurement     : Monitor network lag/delay in milliseconds (ms).
3. Packet Loss Analysis    : Detect network instability or faulty cabling/switches.
4. MTU Path Discovery      : Test maximum payload sizes without packet fragmentation.
5. Local Gateway Check     : Determine if a connectivity issue is local or external.


3. KEY FLAGS & COMMAND VARIATIONS
--------------------------------------------------------------------------------
Task                                    Command
--------------------------------------------------------------------------------
Ping domain continuously (Cancel: Ctrl+C): ping google.com
Limit ping count (e.g., 4 packets)      : ping -c 4 8.8.8.8
Change ping interval (e.g., every 2s)   : ping -i 2 8.8.8.8
Set timeout for response (e.g., 5s)     : ping -w 5 8.8.8.8
Audible ping (Beep on reply)            : ping -a 8.8.8.8
Flood ping (Stress test - Requires root): sudo ping -f 192.168.1.1
Custom packet size (e.g., 1000 bytes)   : ping -s 1000 8.8.8.8
Do Not Fragment flag (Test MTU size)    : ping -M do -s 1472 8.8.8.8
Ping specific interface (e.g., ens33)   : ping -I ens33 192.168.1.1


4. SAMPLE OUTPUT BREAKDOWN
--------------------------------------------------------------------------------
Command: ping -c 3 google.com

Sample Output:
PING google.com (142.250.190.46) 56(84) bytes of data.
64 bytes from maa05s18-in-f14.1e100.net (142.250.190.46): icmp_seq=1 ttl=117 time=14.2 ms
64 bytes from maa05s18-in-f14.1e100.net (142.250.190.46): icmp_seq=2 ttl=117 time=13.8 ms
64 bytes from maa05s18-in-f14.1e100.net (142.250.190.46): icmp_seq=3 ttl=117 time=14.1 ms

--- google.com ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2003ms
rtt min/avg/max/mdev = 13.821/14.041/14.210/0.160 ms

Metrics Explained:
- icmp_seq=1           : Sequential packet number.
- ttl=117              : Time To Live (Number of router hops remaining before drop).
- time=14.2 ms         : Round Trip Time (RTT) taken for packet to reach & return.
- 0% packet loss       : Health indicator (0% is ideal, >0% indicates network issues).
- rtt min/avg/max/mdev : Minimum, Average, Maximum, and Mean Deviation latencies.


5. REAL-WORLD TROUBLESHOOTING SCENARIO
--------------------------------------------------------------------------------
Scenario: Server cannot reach `google.com`. Need to isolate where network fails.

Troubleshooting Steps (Standard Escalation Path):
1. Ping Loopback Interface  : `ping -c 2 127.0.0.1`
                              (If fails -> Local TCP/IP stack is broken).
2. Ping Local IP Address    : `ping -c 2 192.168.1.100`
                              (If fails -> Local NIC driver/card is down).
3. Ping Local Gateway       : `ping -c 2 192.168.1.1`
                              (If fails -> Router/Cable issue on local LAN).
4. Ping External Public IP  : `ping -c 2 8.8.8.8`
                              (If succeeds -> Internet is UP, but DNS is broken!).
5. Ping Domain Name         : `ping -c 2 google.com`
                              (If fails here but step 4 worked -> Fix `/etc/resolv.conf`).


6. REVISION CHEATSHEET
--------------------------------------------------------------------------------
- Always use `-c <count>` in scripts to prevent infinite loops.
- `Destination Host Unreachable`: No route to the IP (Check Gateway/Routing).
- `Request Timed Out` / `100% packet loss`: Firewall is blocking ICMP or target is down.
- Some cloud providers (AWS EC2, Cloudflare) block ICMP by default for security.
================================================================================
                                END OF NOTES
