####################################################################
1. VIRTUAL NETWORK (VNET)
####################################################################

VNet = Virtual Network.

It is a logically isolated private network created inside Azure.

We can think of a VNet as our own network boundary inside Azure.

Example:

VNet
Address Space: 10.10.0.0/16


Architecture:

Azure
 |
 +---- VNet
        |
        +---- Subnet-1
        |
        +---- Subnet-2
        |
        +---- Subnet-3


Resources such as:

- Virtual Machines
- Load Balancers
- Application Gateways
- Private Endpoints
- Azure Firewall
- Virtual Network Gateways

can use networking inside or connected to a VNet.


Main purpose of VNet:

1. Network isolation
2. IP address management
3. Communication between Azure resources
4. Connection to Internet
5. Connection to On-Premises network
6. Traffic routing
7. Network security


Example:

VNet Address Space:

10.10.0.0/16

This means the VNet owns the address range:

10.10.0.0 - 10.10.255.255


====================================================================
2. CIDR
====================================================================

CIDR = Classless Inter-Domain Routing.

CIDR tells us how many bits belong to the network portion.

Example:

10.10.0.0/16


IPv4 address = 32 bits.

So:

/16 = first 16 bits are network bits.

Remaining:

32 - 16 = 16 host bits.


Total addresses:

2^(32 - prefix)

Example:

/24

2^(32-24)
= 2^8
= 256 total addresses.


Common CIDRs:

/16 = 65,536 addresses
/17 = 32,768
/18 = 16,384
/19 = 8,192
/20 = 4,096
/21 = 2,048
/22 = 1,024
/23 = 512
/24 = 256
/25 = 128
/26 = 64
/27 = 32
/28 = 16


====================================================================
3. SUBNET
====================================================================

A subnet is a smaller network created inside a VNet.

Example:

VNet:

10.10.0.0/16


We can divide it into:

WebSubnet:

10.10.0.0/24


AppSubnet:

10.10.1.0/24


DBSubnet:

10.10.2.0/24


Architecture:

VNet
10.10.0.0/16
 |
 +---- WebSubnet
 |      10.10.0.0/24
 |
 +---- AppSubnet
 |      10.10.1.0/24
 |
 +---- DBSubnet
        10.10.2.0/24


Subnets allow us to:

- Separate workloads
- Apply different security rules
- Apply different routing rules
- Organize infrastructure
- Create network boundaries


Important:

Subnet ranges inside the same VNet must NOT overlap.


Wrong:

Subnet-A:
10.10.0.0/24

Subnet-B:
10.10.0.128/25


These overlap.

Therefore this is invalid.


====================================================================
4. AZURE RESERVED IP ADDRESSES
====================================================================

Azure reserves 5 IP addresses in every subnet.

Example:

Subnet:

10.10.0.0/24


Total IP addresses:

256


Azure reserves the first four and last IP addresses.

Conceptually:

Network address
Azure default gateway
Azure DNS-related infrastructure
Azure internal reservation
Last address


Therefore:

256 total addresses
-
5 reserved addresses
=
251 usable addresses for resources.


Important:

Azure subnet usable IP calculation is different from the traditional
"network address and broadcast address only" explanation used in many
basic networking examples.


====================================================================
5. VLSM
====================================================================

VLSM = Variable Length Subnet Mask.

Instead of giving every subnet the same size, we allocate subnet sizes
based on requirements.

Example requirements:

WebSubnet = 100 resources
AppSubnet = 50 resources
DBSubnet = 20 resources


Possible design:

WebSubnet:

10.10.0.0/25


AppSubnet:

10.10.0.128/26


DBSubnet:

10.10.0.192/27


The mindset should be:

Requirement
   |
   v
How many addresses are required?
   |
   v
Choose suitable CIDR
   |
   v
Allocate subnet
   |
   v
Check overlap


Do NOT always think:

"I need 5 subnets, so how many bits should I borrow?"

Better thinking:

"How many resources does each subnet need?"

9. GATEWAYSUBNET
====================================================================

GatewaySubnet is a special dedicated subnet used for Azure virtual
network gateway resources.

Examples:

- VPN Gateway
- ExpressRoute Gateway


Architecture:

VNet
 |
 +---- WebSubnet
 |
 +---- AppSubnet
 |
 +---- DBSubnet
 |
 +---- GatewaySubnet
         |
         +---- VPN Gateway
               OR
         +---- ExpressRoute Gateway


Normal workload VMs should not be deployed in GatewaySubnet.

GatewaySubnet is reserved for gateway infrastructure.

Common example:

10.10.0.0/16

       v

       |
       v

       |

Important:

The VPN Gateway resource is deployed into GatewaySubnet.

VPN Gateway can support scenarios such as:

- Site-to-Site VPN
- Point-to-Site VPN
- VNet-to-VNet connectivity


Mental model:

VPN Gateway = Secure tunnel between Azure and another network.

13. ROUTING BASICS
====================================================================

Routing answers the question:

"Where should this packet go?"


A route generally contains:

Destination Prefix
        |
        v
Next Hop


Example:

Destination:

10.20.0.0/16


Next Hop:

Virtual Network Gateway


Meaning:

Traffic for 10.20.0.0/16 should go toward the configured gateway.


====================================================================
14. SYSTEM ROUTES
====================================================================

Azure automatically creates system routes.

These provide default connectivity and routing behavior.

Example:

Traffic inside a VNet can be routed based on Azure system routes.


Example:

WebVM
10.10.0.4
       |
       v
System routing
       |
       v
AppVM
10.10.1.4


You do not need to manually create a route just for every subnet inside
the VNet to communicate.


System routes can also reflect Azure connectivity scenarios such as
Internet, peering, and other Azure-provided paths depending on the
configuration.


====================================================================
15. USER DEFINED ROUTES (UDR)
====================================================================

UDR = User Defined Route.

We create custom routes when we want to influence where traffic goes.

Example:

Destination:

0.0.0.0/0


Next Hop:

Azure Firewall


Meaning:

Traffic not matching a more specific route should be sent toward the
Firewall.


Flow:

AppVM
   |
   v
Route lookup
   |
   v
UDR
0.0.0.0/0
   |
   v
Azure Firewall
   |
   v
Internet


Important:

UDR does not filter traffic.

UDR only helps decide the traffic path.


Routing decides:

WHERE traffic goes.


Firewall/NSG decides:

Whether traffic is allowed or denied.

 +---- Route 2
 |

Route tables are associated with subnets.

Example:

AppSubnet
     |
     v

A route table can contain multiple routes.

A route table can be associated with multiple subnets.


Conceptually:

     |          |

Subnet-1     Subnet-2


Azure route tables are regional resources and are associated with

====================================================================
19. LONGEST PREFIX MATCH
====================================================================

If multiple routes match a destination, the most specific matching
prefix is generally selected.

Example:

10.0.0.0/8

10.10.0.0/16

10.10.1.0/24


Destination:

10.10.1.20


All three match.

But:

10.10.1.0/24

is the most specific.


Therefore:

10.10.1.0/24 wins.


Example:

Destination:
10.10.1.20

Matches:

10.0.0.0/8       Yes
10.10.0.0/16     Yes
10.10.1.0/24     Yes


Selected:

10.10.1.0/24


Mental model:

More specific destination = Longer prefix = Preferred match.


If no more specific route exists, a default route such as:

0.0.0.0/0

can act as the catch-all route.

20. NETWORK SECURITY GROUP (NSG)
====================================================================

NSG = Network Security Group.

NSG filters network traffic.

It answers:

Should this traffic be allowed or denied?


NSG rules can evaluate:

- Source
- Destination
- Source port
- Destination port
- Protocol
- Direction


Actions:

Allow
Deny


Example:

Source:

10.10.0.0/24


Destination:

10.10.1.0/24


Protocol:

TCP


Destination Port:

80


Action:

Allow


Meaning:

WebSubnet
    |
    | TCP 80
    v
AppSubnet

Allowed.

21. INBOUND AND OUTBOUND NSG RULES
====================================================================

Inbound:

Traffic coming toward the resource.


Example:

Internet
   |
   v
VM Port 443


Outbound:

Traffic leaving the resource.


Example:

VM
   |
   | HTTPS
   v
Internet


NSG has separate inbound and outbound rules.


====================================================================
22. NSG AT SUBNET LEVEL AND NIC LEVEL
====================================================================

An NSG can be associated with:

1. Subnet
2. NIC


Example:

VNet
 |
 +---- AppSubnet
        |
        | NSG at Subnet
        v
       AppVM
        |
        | NSG at NIC
        v
       NIC


Both applicable security policies can affect traffic.


Conceptually:

Subnet NSG
    |
    v
Traffic
    |
    v
NIC NSG
    |
    v
VM


For traffic to pass, it must not be blocked by an applicable NSG rule.


Example:

Subnet NSG:

Allow TCP 80


NIC NSG:

Deny TCP 80


Final result:

Blocked.


One NSG's Allow does not override another applicable NSG's Deny.


====================================================================
23. NSG IS STATEFUL
====================================================================

NSG is stateful.

Example:

VM
 |
 | Outbound HTTPS request allowed
 v
Internet


The response:

Internet
   |
   v
VM


does not require a separate matching inbound rule just for the return
traffic of that established connection.

Conceptually:

Allowed connection
       |
       v
Connection state tracked
       |
       v
Return traffic allowed for that flow


====================================================================
24. NSG RULE PRIORITY
====================================================================

NSG rules have priorities.

Lower number = Higher priority.


Example:

Priority 100:

Deny TCP 80


Priority 200:

Allow TCP 80


TCP 80 traffic matches priority 100 first.

Result:

Denied.


Once a matching rule is processed, lower-priority rules do not override
that decision for the same flow evaluation.


====================================================================
25. DEFAULT NSG RULES
====================================================================

Azure provides default NSG rules.

Conceptually:

Inbound defaults include:

- AllowVNetInBound
- AllowAzureLoadBalancerInBound
- DenyAllInBound


Outbound defaults include:

- AllowVNetOutBound
- AllowInternetOutBound
- DenyAllOutBound


Custom rules use priorities that are evaluated before the default rules.

28. WHAT PROBLEM DOES ASG SOLVE?
====================================================================

Without ASG:

NSG Rule:

With ASG:

Centralized inspection point.


Architecture:

36. NSG vs AZURE FIREWALL
====================================================================

NSG:

- Subnet/NIC level
- Basic distributed network filtering
- Inbound and outbound rules
- Stateful
- No NAT capability
- Does not control routing
- Uses source/destination/port/protocol/direction


Azure Firewall:

- Centralized managed firewall service
- Deployed in AzureFirewallSubnet
- Stateful
- Advanced traffic inspection
- Network rules
- Application/FQDN rules
- NAT rules
- Can inspect north-south traffic
- Can inspect east-west traffic if routed through it
- Commonly requires UDR steering for outbound/internal traffic paths


Memory line:

NSG = Security at workload boundaries.

Azure Firewall = Centralized inspection on selected traffic paths.

40. COMPLETE PACKET FLOW MENTAL MODEL
====================================================================

When a packet is generated:

1. Source VM creates packet.

2. Azure networking determines applicable route.

3. Effective routes are considered.

4. Destination prefix is matched.

5. Most specific matching route generally wins.

6. Next hop/path is selected.

7. If traffic is routed to a Firewall:
   Firewall inspects it.

8. NSG filtering is applied at applicable subnet/NIC enforcement points.

9. If allowed, traffic reaches destination.
